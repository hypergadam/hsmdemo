# hsmdemo

Small Go program that uses a PKCS#11 HSM (SoftHSM for testing) to:

1. create an ECDSA **P-384** key pair inside the HSM,
2. sign a **SHA-384** hash with the private key,
3. verify the signature with the public key.

The private key is created with `CKA_SENSITIVE=true` and
`CKA_EXTRACTABLE=false`, so it can never leave the HSM.

## Quick start

```bash
sudo dnf install -y golang gcc libtool-ltdl-devel softhsm opensc just
```

(`softhsm` provides the PKCS#11 library, `opensc` provides `pkcs11-tool`.)

```bash
cp .env.example .env     # set HSM_PIN and HSM_SO_PIN
just doctor              # check tools, library, config, PINs and token
just run                 # create the token if missing, then sign and verify
```

Expected output:

```
msg="new key pair created in HSM"
msg="signature checked" valid=true
```

Run `just` on its own to list every recipe.

## Where the token lives

`just` keeps all SoftHSM state inside the project:

```
.softhsm/
  softhsm2.conf      generated by `just init`
  tokens/            the token database
```

It does this by exporting `SOFTHSM2_CONF`, which `libsofthsm2.so` reads when
`C_Initialize` runs. So `softhsm2-util`, `pkcs11-tool` and `go run .` all agree
on one token store, and nothing touches the root-owned system store at
`/var/lib/softhsm/tokens`. No `sudo` anywhere.

`just token-reset` deletes the whole thing (it asks first).

## Settings

| Variable     | Required | Meaning                                               |
|--------------|----------|-------------------------------------------------------|
| `HSM_PIN`         | yes      | User PIN of the token                            |
| `HSM_SO_PIN`      | yes      | Security Officer PIN, only used to create the token |
| `PKCS11_LIB_PATH` | no       | Path to the PKCS#11 library (default: Fedora SoftHSM) |

The name is `PKCS11_LIB_PATH`, matching `main.go`. The container sets it to the
Alpine path, since the Fedora default does not exist there.

`just` loads these from `.env`, which is gitignored. Leave `PKCS11_LIB_PATH`
commented out to get the default — an empty value is an empty override, not a
request for the default.

Find the library path with:

```bash
rpm -ql softhsm | grep libsofthsm2.so
```

## Recipes

| Recipe             | What it does                                           |
|--------------------|--------------------------------------------------------|
| `just doctor`      | Report every prerequisite at once, then exit non-zero  |
| `just run`         | Create the token if missing, then sign and verify      |
| `just objects`     | List token objects — shows the key is non-extractable  |
| `just key-info`    | Attributes of `ca-signing-key` only                    |
| `just slots`       | Slot and token info                                    |
| `just mechanisms`  | EC mechanisms the provider supports                    |
| `just token-reset` | Delete the local token store                           |
| `just check`       | fmt, vet, lint, test                                   |
| `just demo`        | Token, signature, then key attributes                  |

Container recipes:

| Recipe                      | What it does                                 |
|-----------------------------|----------------------------------------------|
| `just image-build`          | Build the image                              |
| `just image-run`            | Run with a throwaway token                   |
| `just image-run-persistent` | Run with a named volume, keeping the key     |
| `just image-shell`          | Shell into the image                         |
| `just image-volume-rm`      | Delete the token volume                      |

## Containers

```bash
just image-build
just image-run                 # throwaway token, discarded with the container
just image-run-persistent      # token kept in the hsmdemo-tokens volume
```

Or without `just`:

```bash
docker build -t hsmdemo .
docker run --rm -e HSM_PIN=1234 -e HSM_SO_PIN=5678 hsmdemo
```

Podman works the same way — `CONTAINER_ENGINE=podman just image-run`, or swap
`docker` for `podman` in the commands above.

Expected output on a fresh token:

```
docker-entrypoint: initialising token "ca-token"
msg="new key pair created in HSM"
msg="signature checked" valid=true
```

Notes on how the image is put together:

- **Both base images are pinned by digest.** Bump them on purpose, not by
  retagging. `golang:1.27.2-alpine3.24` builds, `alpine:3.24` runs.
- **CGO stays enabled.** `miekg/pkcs11` wraps the PKCS#11 C API and links
  `-ldl`, so the build stage installs `gcc` and `musl-dev`. Nothing else is
  needed — in particular not `libtool-ltdl-devel`, which `-ldl` makes
  redundant on both glibc and musl.
- **The image ships no token.** A token cannot be baked in sensibly: it would
  mean committing a private key to a layer. `docker-entrypoint.sh` creates one
  on first start, which is the container equivalent of `just token-ensure`.
- **It runs as an unprivileged user** (`app`, uid 10001) with the token store
  at `/var/lib/hsmdemo/tokens`, declared as a volume.
- **`.dockerignore` keeps `.env`, `.softhsm/` and the host `hsmdemo` binary out
  of the build context** — the local token store holds real test keys.

## Running by hand

Not needed if you use `just`, but for reference. `.softhsm/` is gitignored, so
a fresh checkout has no config yet and the first step has to write one —
exactly what `just init` does:

```bash
mkdir -p .softhsm/tokens
printf '%s\n' \
    "directories.tokendir = $PWD/.softhsm/tokens" \
    'objectstore.backend = file' \
    'objectstore.umask = 0077' \
    > .softhsm/softhsm2.conf

export SOFTHSM2_CONF="$PWD/.softhsm/softhsm2.conf"
softhsm2-util --init-token --free --label ca-token --so-pin 5678 --pin 1234
HSM_PIN=1234 go run .
```

Both halves matter, and they fail differently. Leave `SOFTHSM2_CONF` unset and
SoftHSM falls back to `/etc/softhsm2.conf`, whose `directories.tokendir` is
root-owned, so `--show-slots` fails with `Failed to enumerate object store`.
Point it at a file that does not exist and there is no fallback at all —
SoftHSM stops with `Could not load the SoftHSM configuration`.

## Security notes

- The PINs above are for local testing only. In production use a secret manager
  (Vault, Podman/Docker secrets), not files on disk or command-line arguments.
- SoftHSM is software. It is **not** FIPS 140-3 validated. For production use a
  validated hardware HSM and point `PKCS11_LIB_PATH` at the vendor library.
- Raw ECDSA from PKCS#11 is `r || s`. X.509 needs ASN.1 DER, so convert the
  signature before putting it in a certificate. Implementing `crypto.Signer`
  over the token is the clean way to do this, and it also unlocks
  `x509.CreateCertificate` and friends.
- `just token-init` uses `--init-token --free`, which claims the next free slot.
  Running it twice creates a *second* token with the same label, and
  `findObject` returns the first match — so you could sign with an
  unpredictable key. Prefer `just token-ensure`, which `just run` depends on.
- Keys are found by `CKA_LABEL` alone. A production CA should key off `CKA_ID`
  and have a defined rotation story.
